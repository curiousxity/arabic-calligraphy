# Tarkib Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compose a typed phrase in Thuluth from the mark library's pen pieces inside a chosen shape, offer several arrangements ranked by how little of the shape is left empty, and hand the chosen one to the stack editor window for nudging.

**Architecture:** A generated *piece schema* (letters, form, entry/exit cuts, stretch zones, mark anchors) sits beside the mark library and loads on demand with it. Pure modules read a phrase (`tarkibText`), turn schema pieces into `StackPiece`s cut at their join faces (`tarkibPieces`), chain a connected run (`tarkibChain`), and search variant choice, climbs and stretches inside a shape against an unfilled-space score (`tarkibCompose`, `tarkibScore`), in a Web Worker. The result is an ordinary `stack` block carrying an optional `tarkib` record, so the stack editor window's tools work on it.

**Tech Stack:** TypeScript, React 19, Konva, Vitest; Python 3 (`python -I -X utf8`) with numpy/opencv/potrace for the schema script, as the other mark scripts.

**Spec:** `docs/superpowers/specs/2026-10-18-tarkib-design.md`

## Global Constraints

- Library units: 48 per pen width; `MARK_UNITS_PER_EM` = 400. A tarkib stack block has `unitsPerEm: 400` and `nib: { width: 48, minFraction: FALLBACK_NIB_FLOOR }` (0.5, `src/lib/nuqta.ts`; no Thuluth-specific floor is measured yet).
- Geometry is y-down, centred on each piece's origin, exactly as `markLibraryData.ts` stores it; `parseSvgPath(item.d)` is a piece's `cmds`.
- No static import of `markLibraryData.ts`, `MARK_GROUPS` or the new `tarkibSchemaData.ts` anywhere; both load through `loadTarkibLibrary()` (which calls `loadMarkGroups()`).
- Never scale a letter as a whole; length changes only through stretch zones (`splitPieceAtCut` + translating the cap).
- No canvas handles or modes; editing stays in the stack editor window.
- Typed vowels are used as given; with none typed, `vowelize` is asked; when it answers `not-connected`, compose without vowels and say so in one line. Never invent vowels.
- `src/lib/tarkib*.ts` are pure: no React, no `./harfbuzz` (Vitest cannot load it), no DOM.
- Generated files are never hand-edited: `tarkibSchemaData.ts` comes from `scripts/marks/thuluth/pieceSchema.py`.
- Verification after every task: `npx tsc --noEmit -p tsconfig.app.json`, `npm run lint`, `npm test`, `npm run build`. The pre-commit hook bumps the version; `package.json` changes in every commit.
- Branch `claude/curve-diacritics`; never merge to `main`.
- UI copy is plain language for calligraphers ("Compose in Thuluth", "Arrangements", "Compose again"), no developer terms.

## Review Focus

1. **A phrase with a letter that has no reviewed piece** (e.g. ظ before its schema is reviewed, or a Latin letter, digit or punctuation): composing must refuse with a message naming those letters, never draw a partial phrase or throw. Test in Task 1 (analysis lists `unsupported`) and Task 7 (`composeInShape` returns `{ error }`).
2. **Hamza and alif variants and ta marbuta** (أ إ آ ؤ ئ ة ى): each must map to a skeleton and its hamza/dots, not fall out as unsupported. Test in Task 1.
3. **A shape too small or too thin for the phrase**: the search must stop within its budget and report "doesn't fit", never hang the window. Test in Task 7 (degenerate polygon and a 10 px teardrop return `{ error: "no-fit" }` within `budgetMs`).
4. **Old saves**: a `stack` block without `tarkib` must open, edit and arrange exactly as before (row arranger, font fillers). Test in Task 10.
5. **Partially vowelled input** (vowels on some letters only): those vowels are used and the service is not asked; nothing is added to unvowelled letters. Test in Task 9.

  ```ts
  // src/lib/tarkibSchema.ts
  export type FaceCut = { cutX: number; angle: number };          // splitAtCut's frame, piece units
  export type StretchZone = { cutX: number; angle: number; side: "near" | "far"; min: number; max: number }; // added length, units
  export type PieceSchema = {
    id: string;                                     // mark library id
    letters: { skeleton: string; form: LetterForm; above: Pt; below: Pt }[];  // reading order; mark anchors
    entry?: FaceCut;                                // keep the far side (x > cutX) when cutting here
    exit?: FaceCut;                                 // keep the near side (x < cutX) when cutting here
    stretch: StretchZone[];
    ownDots: boolean;
    noFreeEnd?: true;                               // an end cut on the source sheet: never a free tail
    reviewed: boolean;
  };
  export type TarkibLibrary = {
    items: Map<string, MarkItem>;
    schema: Map<string, PieceSchema>;
    /** `${skeleton}|${form}` -> single-letter pieces, best (reviewed, vector) first */
    single: Map<string, PieceSchema[]>;
    /** first letter's `${skeleton}|${form}` -> multi-letter pieces */
    multi: Map<string, PieceSchema[]>;
    nuqtaD: string;                                 // one Thuluth nuqta outline, centred
  };
  export function loadTarkibLibrary(): Promise<TarkibLibrary>;   // dynamic-imports tarkibSchemaData.ts and calls loadMarkGroups()
  ```
- Generated data shape: `export const PIECE_SCHEMA: PieceSchema[]` and `export const NUQTA_D: string`.

Rules the script implements (from the spec, section 1):
- **Letters and form** parsed from names: vector names `"<Letter>, <position>, n (<glyph>)"` → skeleton from the letter name (`Ba, nun or ya tooth` → `ba`), form from position (`finishing` → `finishing`). Scanned names: the Arabic in the name, split by Task 1's rules in Python (a direct port of the skeleton table; keep the two tables identical — a test compares them, Step 1). Names that do not parse are printed and get `reviewed: false`.
- **Entry/exit**: a starting form has `exit`, finishing `entry`, middle both; multi-letter pieces: entry if the first letter is middle/finishing, exit if the last is starting/middle. The face is a vertical-ish cut across the thin joining run at the piece's right (entry) or left (exit) end, one half pen (24 units) in from the ink's extreme along the run; `angle` is the run's centreline direction there. Thresholds come from `measureJoins.py`'s output, recorded in the script's docstring.
- **Stretch zones**: per skeleton rule — `ba`/`seen`/`sad`/`ta`/`fa`/`kaf` flat run; the kashida run of any join (between the face and the letter body); `ya`/`nun`/`ra`/`waw`/`qaf` tails. Located on the piece by the measure, `min` 0, `max` 4 pens (192 units) for flats and kashida, 3 pens for tails.
- **Anchors**: `above` = (ink box centre x, ink top − 0.5 pen), `below` = (centre x, ink bottom + 0.5 pen), per letter over that letter's share of the ink (single letters: the whole piece).
- **ownDots**: true when the piece has a separate contour of nuqta size (0.6–1.4 pen across, aspect < 1.6). `NUQTA_D`: the cleanest such dot (the one closest to a 1-pen rhombus) from the vector Ba standalone pieces, centred.
- **noFreeEnd**: from a list in the overrides file seeded with the pieces the ledger notes as cut (t2 24 is retired; t7r1 2's tip is borrowed and is free).
- **Overrides** (`schema-overrides.json`, `{ "<id>": Partial<PieceSchema> }`) are applied last; `reviewed` flips to true only through the review (Task 3).

  /** Library-built pieces only: where this piece may lengthen (tarkibSchema.ts StretchZone, piece-local). */

### Task 5: Chain a run on a line, and show it (the user's first check)

**Files:**
- Create: `src/lib/tarkibChain.ts`
- Modify: `src/types.ts` (optional `StackBlock.tarkib`)
- Modify: `src/App.tsx` (`composeThuluthLine` handler), `src/components/sidebar/BlockControlsPanel.tsx` (the button)

**Interfaces:**
- Consumes: `buildPiece`, `BuiltPiece` (Task 4); `analyzePhrase`, `PhraseRun` (Task 1); `assembleStackOutlineReport` (`stackOutline.ts`).
- Produces:
  ```ts
  // types.ts
  export type TarkibRecord = {
    phrase: string;                         // as composed (vowels included if any)
    target: { kind: "template"; template: string; sizeFactor: number } | { kind: "guide"; guideId: number } | { kind: "box" } | { kind: "line" };
    seed: number;
    pieceIds: string[];                     // schema ids used, reading order
  };
  // on StackBlock:
  /** Present on a block composed from the Thuluth piece library (tarkib.md). */
  tarkib?: TarkibRecord;
  // tarkibChain.ts
  export type RunChoice = { schemaIds: string[]; climbs: boolean[]; stretch: Record<string, number> };
  export type ChainedRun = { pieces: StackPiece[]; joins: StackJoin[]; width: number; height: number };
  export const JOIN_GAP = 12;               // units between exit and entry faces along the stroke (a quarter pen)
  export function chainRun(lib: TarkibLibrary, run: PhraseRun, choice: RunChoice, idPrefix: string, orderStart: number): ChainedRun;
  export function defaultChoice(lib: TarkibLibrary, run: PhraseRun): RunChoice | null;   // multi-letter pieces where one matches, else the first single; null if a letter has none
  export function chainPhraseOnLine(lib: TarkibLibrary, text: string): { pieces: StackPiece[]; joins: StackJoin[] } | { error: "unsupported"; letters: string[] };
  ```
  `chainRun` places each next piece so its entry face's midpoint sits `JOIN_GAP` from the previous exit face's midpoint along the exit's tangent (no climb) and adds a `StackJoin` (`bow: 0`, no `profile`). `climbs[i]` true lifts piece i+1 by its own height plus a quarter pen and adds the join anyway (the curve carries the climb; Task 7 uses it). `stretch` (piece id → added units) is applied with `splitPieceAtCut` at the piece's first stretch zone, translating the cap along the zone's axis. Piece ids are `${idPrefix}${i}` for the run's i-th piece (0-based), so `"a1"` is the second piece of run `"a"`. `chainPhraseOnLine` lays runs right to left with one pen between runs and two between words, baseline aligned, `order` increasing in reading order.

### Task 6: The unfilled-space score

**Files:**
- Create: `src/lib/tarkibScore.ts`
- Test: `src/lib/tarkibScore.test.ts`

**Interfaces:**
- Consumes: `assembleStackOutline` (`stackOutline.ts`); `flattenContours` (`strokeCuts.ts`); `pointInPolygon` (`svgPath.ts`).
- Produces:
  ```ts
  export type TarkibScore = { total: number; unfilled: number; outside: number; overlap: number; order: number; overStretch: number; uneven: number };
  export const SCORE_WEIGHTS: { unfilled: 1; outside: 20; overlap: 6; order: 50; overStretch: 10; uneven: 0.5 };   // tunables
  export const FILL_MARGIN = 0.5;           // pens: shape area within this of ink counts as filled
  export const SCORE_CELL = 0.25;           // pens: grid cell
  export function scoreLayout(input: {
    pieces: readonly StackPiece[]; joins: readonly StackJoin[]; nib: { width: number; minFraction: number };
    shape: readonly Pt[];                   // units, same frame as the pieces
    readingOrder: string[];                 // letter piece ids in reading order
    stretchUsed: Record<string, { used: number; max: number }>;
  }): TarkibScore;
  ```
  `unfilled`: share (0..1) of grid cells inside `shape` whose centre is farther than `FILL_MARGIN` pens from ink (distance on the cell grid, two-pass chamfer). `outside`: share of ink cells outside the shape. `overlap`: share of ink cells covered by two letters of different reading-order groups (a letter and its own marks or stretch caps do not count). `order`: count of letter pairs (i, j>i) where j's ink centre is right of i's by more than a pen *and* not above i's top (a climbed letter may sit right). `overStretch`: Σ max(0, used − max) / pen. `uneven`: standard deviation of tier ink heights / mean (tiers: letters grouped by their row from the layout, passed through `pieces` order). `total` = Σ weight × term.

Keep the best `count` layouts whose piece-id lists differ by at least 25% of letters (distinctness). Fillers run last on each kept candidate (`fillGaps` path of `stackArrange.ts`, with the given fillers). Progress is reported every 5% of budget.
